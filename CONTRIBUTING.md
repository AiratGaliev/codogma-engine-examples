# Как добавлять примеры

## Критерии отбора

Добавляйте пример, только если он приносит отдельную ценность для пользователя редактора или покрывает интеграционный сценарий, который не демонстрируют существующие проекты. Небольшой code-only сниппет без редактируемой сцены не подходит для основной коллекции.

## Обязательная структура проекта

- `README.md` с назначением, управлением, тем, что изучать в Scene Editor, и ограничениями.
- `index.html` с закреплённой версией Phaser 4.2.1.
- `tsconfig.json`, `main.ts` и исходный TypeScript сцены.
- Как минимум одна настоящая сцена `.scene`; для Prefab-примера — сцена Prefab и сцена с его экземплярами.
- У объектов устойчивые уникальные идентификаторы; названия объектов понятны и пригодны для Hierarchy.
- Внешние ассеты сопровождаются лицензией, источником и разрешением на повторное распространение. Не переносите ресурсы из Phaser Examples без отдельного подтверждения лицензии: код и ресурсы этого репозитория лицензируются по-разному.

## Проверки перед PR

```bash
npm install --no-audit --no-fund
npm test
npm run build
```

Дополнительно вручную откройте проект в Codogma Engine, измените и сохраните сцену, переоткройте её и запустите собранную игру в браузере. В PR указывайте, какие из этих действий действительно выполнены.

## Правила

- Не смешивайте в одном примере несвязанные возможности.
- Сохраняйте изменения сцены и скомпилированного кода согласованными.
- Не коммитьте `game.js`, `node_modules` и другие генерируемые файлы.
- Не помечайте будущие функции движка как готовые; фиксируйте неподтверждённые возможности в каталоге отдельно.
